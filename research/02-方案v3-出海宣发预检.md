## 1. 一句话

**Clear the creative. Clear the calendar.**
给出海的 AI/Agent 产品团队用：上线前把**宣传物料**过一遍目标市场的文化与合规雷区（宣），再给每个市场找一个不撞档、不踩敏感日的**发布周**（发）。

- **市场**：韩国、新加坡、美国。
- **垂类**：AI/Agent 产品。用户是这些产品的 PMM 和增长负责人，宣发本来就是他们的活。
- 选这个垂类的理由：
  - 评委懂；
  - 案例新、足够多（2024–2026 年 AI 广告翻车集中爆发）；
  - 中国 AI 公司出海正在发生（DeepSeek 在韩被暂停下载就是活教材）。

## 2. 两个模块

### 2.1 宣：素材预检

**输入**：KV/海报、视频关键帧、Slogan、发布文案、落地页链接，以及目标市场和受众分群。

**过程**：
1. 多模态模型看图、读文案，抽取"信号"：手势、人物、肤色与妆造、旗帜和地图、食物、宣称用语、隐私说明等。
2. 用信号检索 `rules.yaml`，**只有命中规则才能下结论**，并附上关联案例和出处。
3. 输出风险卡片：严重度、图上位置（bbox）、为什么、怎么改、真实案例。
4. 生成本地化版本（文案实时改写；图片 Demo 阶段用预制变体保证稳定），然后**复检**，展示前后分数。

**三个市场的主打雷区**（都有已核实案例）：

| 市场 | 雷区 | 代表案例 |
|---|---|---|
| 🇰🇷 | 捏手势；万圣节档期；数据跨境与隐私；AI 人设 | iPhone Air 韩国版删手指（2025）、GS25（2021）、冒险岛（2023）、梨泰院后连续 4 年停做万圣节营销、DeepSeek 被暂停下载（2025）、이루다（2021） |
| 🇺🇸 | "AI 取代人类/碾碎创作"叙事；AI 代笔情感；夸大能力宣称；AI 生成的假评价 | Apple Crush（2024）、Gemini Dear Sydney（2024）、Artisan Stop Hiring Humans、FTC Operation AI Comply / DoNotPay（2024） |
| 🇸🇬 | 种族表现（一人扮多族、棕脸）；宗教与饮食；鬼月档期；国家象征 | NETS E-Pay brownface（2019）、开发商避开鬼月发布 |

### 2.2 发：Clear Run 档期

直接复用 ClearRun 的 Audience Pressure 引擎（`src/engine/score/calendar.ts`）。只把"对手"换掉：

| ClearRun（电影版） | 出海版 |
|---|---|
| 对手 = 同期上映的电影和游戏（维基百科片单） | 对手 = `calendar.yaml` 里的科技发布会、购物节、长假、全民事件 |
| size = 维基 pageviews | 同样：用该语言版维基 pageviews 校准 `attention`（例如韩语维基的"추석"、英文维基的"WWDC"） |
| overlap = Qloo 口味重叠 | overlap = 事件对受众分群的影响（开发者、专业用户、消费者、企业、学生），由知识库给出，可解释 |
| decay（电影 4 周票房衰减） | 改成发布热度衰减：AI 产品的声量衰减更快，大约 3 周 |
| 季节系数（美国假日） | 三个市场各自的假日系数 |
| hold/move 判定 | 保留：你定的日期是"守住"还是"挪开"，挪到哪周 |
| what-if、watch、share 卡片 | 全部保留：比如"假如 OpenAI DevDay 定在这周"可以实时重算 |
| 无工具基线对照（baseline） | 保留并换题：同一个模型不带知识库回答"这张海报能在韩国发吗"，展示它漏掉了什么（需实测） |

**新增两点**：
- **敏感日不算压力，而是"主题条件拦截"**。比如万圣节档期本身能发产品，但素材里如果有派对、南瓜元素就会被拦下。这正好把"宣"和"发"连起来，是 Demo 的亮点。
- **多市场错峰**：给出"美国 W1 → 新加坡 W2 → 韩国 W4"这类分市场上线计划，并解释每个市场为什么选那一周。

| 文件 | 内容 | 数量 |
|---|---|---|

| [knowledge/rules.yaml](../knowledge/rules.yaml) | 可检索的规则：信号 → 原因 → 改法 → 案例 | 17 条（已核实 8，部分核实 3，未核实 6） |
| [knowledge/calendar.yaml](../knowledge/calendar.yaml) | 2026-11 至 2027-10 三个市场的宣发日历 | 43 条（法定假日来自 Nager.Date；发布会日期为估计，需标"预计"） |

**原则**：
- 模型只能引用知识库下结论。未核实（`verified: false`）的条目在 UI 上显示"待核实"。
- 规模目标是每个市场 15–20 条规则。不追求全，**追求每条都经得起评委追问**。
- 捏手势这类有争议的条目要中立表述：只说明"在韩国会引发争议"，不判断争议本身对错。

## 4. 三个主打案例（Demo 剧本）

> 用一个虚构的中国 AI Agent 产品贯穿全程，例如"Mira Agent"（名字待定，别用真实品牌）。它要同时进入美国、新加坡、韩国三个市场。

### 案例 A · 韩国：同一张 KV，韩国要单独出一版
1. 上传全球统一的 KV：一只手用拇指和食指捏着手机，屏幕上是 Agent 界面。
2. 美国和新加坡显示 ✅；**韩国显示 🔴 KR-G01 捏手势**，图上框出手的位置，旁边并排列出 GS25、冒险岛、**Apple iPhone Air 韩国版**三个案例。
3. 一键生成韩国版（手掌托举），复检通过。
4. 落地页扫描：🔴 KR-D01 没有韩文隐私政策和数据存储说明（关联 DeepSeek 案例）。
5. **发**：候选窗口是 2027 年 1–3 月。避开设날（2/6–2/9）和三星 Unpacked（预计 1–2 月），推荐 3 月初新学期窗口（如果受众是学生）。

> 评委记忆点：*"Apple 花钱请本地团队做的事，我们 3 秒做完。"*

### 案例 B · 美国：AI 叙事踩雷
1. 输入发布文案："Fire your assistant. Hire Mira." 和 "100% accurate, never hallucinates."
2. 🔴 US-M01："取代人类"叙事（Artisan、Crush、Dear Sydney）；🔴 US-L01：没有证据的能力宣称（FTC Operation AI Comply）。
3. 改写为增强叙事加可验证数据，例如 "Give your team back 10 hours a week"，复检通过。
4. **发**：压力日历显示感恩节、黑五和年底假期是红色区域，CES 和超级碗是高压周；what-if 演示"假如 OpenAI 这周开发布会"后重新推荐。

### 案例 C · 新加坡：多元种族与档期
1. 视频关键帧里，同一位演员化妆扮演华人、马来人、印度人三个角色。
2. 🔴 SG-R01，关联 NETS E-Pay brownface 案例。
3. **发**：避开农历新年那一周；如果是消费类产品，避开鬼月（2027 年约 8 月）；B2B 产品可以考虑金融科技节周。

**收尾**：一页"三市场宣发预检报告"加分享卡片，ClearRun 的 OG 卡片可以直接复用。

## 5. 一周开发计划（单人开发）

| 天 | 日期 | 目标 | 交付 |
|---|---|---|---|
| D1 | 11-12 | Fork ClearRun；去掉 Qloo 依赖；YAML 知识库加载和类型定义；做 3 个案例的素材 | 能跑起来的空壳 + 素材 |
| D2 | 11-13 | **宣**：视觉模型抽取信号 → 规则检索 → 风险卡片（含 bbox 和出处）；结构化 JSON 输出 | 案例 A 走通 |
| D3 | 11-14 | **发**：日历引擎改造（读 calendar.yaml、受众分群 overlap、主题条件拦截、多市场错峰） | 三个市场的压力日历 |
| D4 | 11-15 | Agent 编排（`scan_creative / plan_launch / rewrite / explain_rule`）；报告页；改稿和复检 | 案例 B、C 走通 |
| D5 | 11-16 | 补齐知识库并核实出处；baseline 对照；离线 mock 模式（ClearRun 的 `dev:mock` 思路） | Demo 不依赖网络也能演示 |
| D6 | 11-17 | 打磨案例和 UI（默认用 Anthropic 风格）；分享卡片；部署到 Cloudflare | 线上可访问 |
| D7 | 11-18 | 路演稿和彩排；留出缓冲 | 提交 |

**技术**：沿用 ClearRun 栈（Vite + React，Cloudflare Workers + D1，OpenRouter）。看图建议用多模态能力强的模型，文案和日历用便宜快速的模型。

**砍需求的顺序**（时间不够时）：多市场错峰 → baseline 对照 → watch 和 re-plan → 图片变体（保留预制图）。**宣的风险卡片和发的压力日历不能砍。**
